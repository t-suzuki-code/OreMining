## コンセプト

- Minecraftの鉱石採掘をミニゲーム化したプラグインです
- コマンドを実行するとポータルが出現し、入ると毎回ランダムに生成される採掘ワールドに移動します
- 制限時間内に坑道を掘り進め、鉄・金・ダイヤモンド鉱石を採掘してハイスコアを目指します
- デイトラJavaコース上級編の課題をベースに、ワールドの動的生成・テレポート・ゲーム状態管理などを
  独自に拡張して実装しました

&nbsp;

## 概要

- プレイヤーが `/gameSetup` コマンドを実行すると、目の前にネザーポータルが出現します
- ポータルに入ると採掘専用ワールドに移動し、制限時間60秒の採掘ゲームが始まります
- ブランチマイニング型の坑道で鉄・金・ダイヤモンド鉱石を採掘し、スコアを競います
- 同じ種類の鉱石を3回連続で採掘するとコンボボーナスが発生します
- 制限時間終了後、スコアはデータベースに保存され、`/viewScore` コマンドでランキングを確認できます

## 遊び方

### 1. ゲームの準備

- `/gameSetup` コマンドを実行すると、プレイヤーの前方にネザーポータルが生成されます
- プレイヤーの装備はリセットされ、ネザライトのツルハシと火打石が配布されます
- 30秒以内にポータルに入らなかった場合、ポータルは自動的に削除されます

### 2. 採掘開始

- ポータルに入ると採掘専用ワールドにテレポートし、ゲームが開始されます
- 制限時間は60秒です
- 画面下部のアクションバーに現在のスコアと残り時間が常時表示されます

### 3. 鉱石を採掘する

- 坑道の壁に埋まっている鉱石を採掘してスコアを稼ぎます
- 採掘するとチャット欄に獲得ポイントが通知されます
- 同じ種類の鉱石を3回連続で採掘するとコンボボーナスが発動します

### 4. スコアを確認する

- `/viewScore` コマンドを実行すると、スコアランキングの上位10件が表示されます

| コマンド | 説明 |
| --- | --- |
| `/gameSetup` | ゲームの準備を開始する（ポータル生成） |
| `/viewScore` | スコアランキングの上位10件を表示する |

## ゲームのルール

### スコア

| 鉱石 | 獲得ポイント | 出現率 |
| --- | --- | --- |
| 鉄鉱石 | 10点 | 50% |
| 金鉱石 | 20点 | 30% |
| ダイヤモンド鉱石 | 30点 | 20% |

### コンボボーナス

- 同じ種類の鉱石を3回連続で採掘すると **+30点** のボーナスが加算されます
- ボーナス発動後、連続カウントはリセットされます

### 中断処理

- ゲーム中にプレイヤーが死亡した場合、元のワールドにリスポーンし、ゲームは中断されます
- ゲーム中にログアウトした場合、再ログイン時に元のワールドに復帰します
- 中断されたゲームのスコアはデータベースに保存されません

## 導入方法

### 1. 環境の準備

- Java 21 以上をインストールしてください
- Spigot 1.21.11 のサーバーを用意してください
- MySQLをインストールし、起動してください

### 2. データベースの準備

- MySQLに接続し、以下のSQLを実行してテーブルを作成してください

```sql
CREATE TABLE oremining_player_score (
    id INT AUTO_INCREMENT PRIMARY KEY,
    player_name VARCHAR(255),
    score INT,
    registered_at DATETIME
);
```

- `src/main/resources/mybatis-config.xml` のDB接続情報をご自身の環境に合わせて変更してください

> **⚠️ 注意**  
> リポジトリに含まれるパスワードはローカル開発用のサンプル値です。  
> 公開環境で使用する場合は、必ずご自身で安全なパスワードに変更してください。

### 3. プラグインのビルド

- 本リポジトリをクローンしてください

```bash
git clone https://github.com/t-suzuki-code/OreMining.git
```

- プロジェクトディレクトリで以下のコマンドを実行し、JARファイルを生成してください

```bash
./gradlew shadowJar
```

- `build/libs/` に生成されたJARファイルをサーバーの `plugins/` フォルダに配置してください

### 4. サーバーの起動

- サーバーを起動し、Minecraftからサーバーに接続してください
- `/gameSetup` コマンドでゲームが開始できれば導入完了です

## 設計・工夫したところ

### 状態管理の一元化

- ゲームの状態を `GameState` 列挙型（IDLE / READY / PLAYING）で管理しています
- 当初はboolean型のフラグ2つ（isGameReady / isGamePlay）で状態を管理していましたが、ありえない状態の組み合わせ（両方true等）が発生し得る問題がありました
- 列挙型に置き換えることで、状態の遷移を明確にし、不正な状態を型レベルで防止しています

### 単方向の依存関係

- コマンドやリスナーは `GameStateManager` に通知するだけの薄いクラスとし、判断・制御のロジックを `GameStateManager` に集約しました
- `SchedulerManager` がスコアを取得する際には `Supplier<Integer>` を、制限時間終了の通知には `Runnable` をコールバックとして使用し、クラス間の依存方向を単方向に保っています
- これにより、循環依存を回避しつつ、各クラスの責務を明確に分離しています

### 異常系の網羅的な処理

- ゲーム中の死亡、ログアウト、コマンドの連打など、正常フロー以外のケースを網羅的に処理しています
- 死亡→ログアウト→再ログインのような複合的な中断パターンにも対応し、状態の不整合が起きないよう設計しました

### リソース管理の改善

- データベース接続には `try-with-resources` を使用し、`SqlSession` の開閉を各メソッド内で完結させています
- 当初はコンストラクタでセッションを開きMapperをフィールドに保持する方式でしたが、セッションがクローズされないリソースリークの問題がありました
- メソッドごとにセッションを都度開閉する方式に変更し、リソースリークの解消とMyBatisのキャッシュ問題の根本解決を同時に実現しました

### 採掘エリアの自動生成

- `VoidChunkGenerator` でデフォルトの地形生成を無効化し、完全に空のワールドを生成しています
- その上に `MiningAreaBuilder` がブランチマイニング型の坑道構造（岩盤の殻・十字型メイン通路・枝通路・グローストーン照明・ランダム鉱石配置）を構築します
- ゲーム終了時にはワールドのアンロードとディスク上のファイル削除を行い、サーバーのリソースを解放しています

## クラス構成

```
plugin.oremining/
├── Main.java                          ... プラグインのエントリーポイント（配線のみ）
├── GameState.java                     ... ゲーム状態の列挙型（IDLE / READY / PLAYING）
├── GameStateManager.java              ... ゲームの状態管理と進行制御
├── SchedulerManager.java              ... 制限時間管理・アクションバー表示
├── WorldGeneration.java               ... 採掘ワールドの生成・削除
├── VoidChunkGenerator.java            ... 空のチャンク生成
├── MiningAreaBuilder.java             ... 採掘エリアの構築・鉱石配置
├── PlayerUtils.java                   ... プレイヤー状態のリセット
├── DBManager.java                     ... DB接続・スコアの保存/取得
├── command/
│   ├── BaseCommand.java               ... コマンドの基底クラス（プレイヤー判定）
│   ├── GameSetupCommand.java           ... ゲーム準備コマンド
│   └── ViewScoreCommand.java           ... スコア一覧表示コマンド
├── listener/
│   ├── WorldTeleportListener.java      ... ポータル通過の検知
│   ├── GameScoreListener.java          ... 鉱石採掘の検知・スコア加算
│   └── GameInterruptListener.java      ... 死亡・ログアウト等の中断処理
└── mapper/
    ├── PlayerScoreMapper.java          ... MyBatis Mapperインターフェース
    └── data/
        └── PlayerScore.java            ... スコア情報のエンティティ
```
